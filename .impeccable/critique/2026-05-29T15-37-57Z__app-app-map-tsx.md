## Anti-Patterns Verdict

**LLM assessment:** This page does not scream "AI made this." It avoids the absolute bans (no gradient text, no glassmorphism blur, no side-stripe borders). The dark map with floating panels is a well-established pattern in GPS/map tools, and the implementation is restrained. However, at the second-order level, it falls into a category reflex: "GPS tracker that's not cluttered → clean dark map with bottom sheet." The aesthetic choices are functional-first, which is correct for this product, but there's little that feels deliberately *crafted* rather than *implemented*. The pulsing marker is the only element with design intent beyond "put the data on screen."

**Deterministic scan:** Detector unavailable — `detect.mjs` is not bundled. No automated findings.

## Overall Impression

This is a focused, competent map detail view that does its job without fuss. The data hierarchy (address → speed → date/time) is sensible, the marker animation is purposeful, and the loading/error states for the reverse geocode are handled. The main drag is a subtle drift from the design system — the page uses custom translucent backgrounds and the `glassBorder` token instead of the standard `border` token, and two font sizes are hardcoded outside the typography scale. It works, but it doesn't feel like it shares DNA with the rest of the app.

## What's Working

1. **The pulsing marker is well-executed.** Two-animation loop (opacity fade + scale) with proper ReduceMotion support, correct `tracksViewChanges={false}`, and restrained size. It signals "current position" without competing with the underlying map.

2. **State management for the address field is thorough.** Loading spinner with text ("Buscando endereço..."), error state with message display, and loaded state with icon + text. The ActivityIndicator placement inside the panel (not blocking the map) is the right call.

3. **Entry animations are tasteful.** Staggered FadeIn/FadeInDown with increasing delays (200→300→500ms) creates a natural reveal hierarchy: back button first, then coordinates, then the instrument panel. The springify on the panel entrance adds a subtle bounce without being distracting.

## Priority Issues

### [P1] Hardcoded font sizes outside the typography scale

- **What:** `coordLabel` uses `fontSize: 9` and `dataValue` uses `fontSize: 22` — both hardcoded numbers instead of theme tokens. 9px doesn't exist in the typography scale (smallest is `overline: 10`). 22px matches `button: 22` but isn't referenced.
- **Why it matters:** Breaks the typography system's consistency. If the scale changes, these values won't update. 9px may be illegible on lower-density screens or for users with visual impairments.
- **Fix:** Use `getTypography("overline")` (10px) for coordLabel, and `getTypography("button")` (22px) for dataValue.
- **Suggested command:** `typeset`

### [P1] Address error has no retry mechanism

- **What:** When `reverseGeocode` fails, the error message is shown but the user has no way to retry. The only recovery path is pressing "Voltar" and coming back.
- **Why it matters:** Fleet managers in the field with intermittent connectivity will see error states frequently. Having to leave and re-enter the map to retry is friction.
- **Fix:** Add a "Tentar novamente" button that re-triggers the geocode fetch, or auto-retry with exponential backoff.
- **Suggested command:** `harden`

### [P2] No validation for missing/invalid coordinate params

- **What:** `const lat = Number(latitude)` and `const lon = Number(longitude)` with no guard. If `latitude` or `longitude` is undefined, null, or non-numeric, `lat`/`lon` become `NaN`, which the map will render incorrectly or crash.
- **Why it matters:** Silent NaN propagation leads to a broken map with no error feedback to the user.
- **Fix:** Validate before rendering: if `isNaN(lat) || isNaN(lon)`, show an error state with a message and back button.
- **Suggested command:** `harden`

### [P2] Translucent overlay drift from design system

- **What:** The instrument panel, back button, and top strip use custom inline `rgba(15,15,15,0.85/0.92)` backgrounds + `Colors.glassBorder` borders, instead of the design system's opaque `backgroundLight` (#1a1a1a) + `Colors.border` (#ffffff26). The gradient overlay height (280px) is also hardcoded.
- **Why it matters:** These elements will look subtly different from other surfaces in the app (login, accounts, history). While translucency makes sense for map overlays, it should either be an intentional design system extension or match the system tokens.
- **Fix:** Either promote "map overlay" as a new surface variant in the design system, or align with existing tokens. At minimum, reference the existing `glassBackground` (rgba(26,26,26,0.8)) token instead of custom inline values.
- **Suggested command:** `extract`

### [P3] Missing empty/error state for the map itself

- **What:** If the map fails to load or the coordinates are invalid, there's no fallback. The page assumes coordinates are always valid and the map always renders.
- **Why it matters:** Edge cases like corrupted navigation params or a failed MapView render leave the user looking at a blank screen.
- **Fix:** Add a guard for invalid coordinates before the map renders, and a Suspense-catch for the MapView.
- **Suggested command:** `harden`

## Persona Red Flags

**Alex (Power User)** — Uses the map to verify fleet positions daily:
- No way to switch between recent coordinates without going back to the list
- Can't tap the address to copy it to clipboard (common need for fleet managers)
- No gesture shortcuts (long-press to share, double-tap to center)
- Risk: will bounce out to the list and back, again and again

**Jordan (First-Timer)** — New fleet manager checking their first vehicle:
- "LAT" and "LNG" labels without explanation — does Jordan know these are latitude/longitude?
- No hint about what the pulsing marker means — it's intuitive but unlabeled
- The speed badge shows a numeric value but what does "stopped" mean exactly? (engine off, parked, idling?)
- Risk: mild confusion about the data, but the clean layout prevents panic

**Sam (Occasional User)** — Supervisor checking a specific vehicle once a week:
- The address display is the most useful piece of information but loads slowly (network geocode)
- No cached/saved address — always waits for the network
- Risk: impatience during address loading; wonders why the address can't be embedded in the data

## Minor Observations

- The gradient overlay `locations={[0.4, 1]}` and `height: 280` are tuned for a specific screen size; on very small or large devices the gradient may look off
- `lineHeight: getTypography("body") * 1.45` generates 23.2px line-height — use Typography.lineHeight.normal (1.5) consistently for body text
- The map has `showsCompass={false}` and `showsScale={false}` — consider conditionally showing the compass when the map is rotated
- No haptic feedback on the back button press (common on native navigation)
- The speed badge moving/stopped state uses border color change — consider adding a subtle icon fill change too for glanceability
- The `PulsingMarker` component is defined in the same file — worth extracting to a shared component if other map views will use it

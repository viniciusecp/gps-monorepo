# Coding Standards

## Overview

TypeScript monorepo with consistent coding patterns across server (Biome) and app (ESLint).

## Code Formatting

**Server**: Biome 2.14 (tabs for indentation, double quotes)
**App**: ESLint 9 via eslint-config-expo

### Key Settings

- **Indentation**: Tabs
- **Quotes**: Double quotes
- **Trailing commas**: Always (Biome), standard (ESLint)
- **Import organization**: Automatic via Biome organizeImports

## Naming Conventions

| Element | Convention | Example |
|---------|------------|---------|
| Variables/functions | camelCase | `getUserById` |
| Classes | PascalCase | `AuthService` |
| Files | kebab-case | `auth-service.ts` |
| Routes | kebab-case | `/api/cliente/login` |
| Database tables | lowercase | `cliente`, `bem`, `gprmc` |

## File Organization

### Project Structure

```

```

## Error Handling

**Pattern**: Fastify error handler + AppError class
**Approach**: Centralized error handling in `app.ts`, custom AppError with status code mapping

### Guidelines

- Throw `AppError` with appropriate status codes
- Catch errors in controllers, pass to Fastify error handler
- Log errors at appropriate levels

## Logging

**Tool**: pino 10.3.1 (with pino-pretty 13.x for dev)

### Log Levels

| Level | Usage |
|-------|-------|
| error | Unhandled exceptions, database failures |
| warn | Unexpected but recoverable issues |
| info | Request lifecycle, auth events |
| debug | Development troubleshooting |

## Import Order

**Rules**:
- External dependencies first (fastify, zod, drizzle-orm)
- Internal modules grouped by layer (services before repositories)
- No barrel files — explicit imports preferred

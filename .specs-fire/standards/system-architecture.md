# System Architecture

## Overview

Two-tier GPS tracking system: Fastify REST API backend with MySQL database, consumed by an Expo React Native mobile app.

## Architecture Pattern

**Pattern**: Layered architecture (server) + Client-server (app)
**Rationale**: Clean separation of concerns via routes → controllers → services → repositories on the backend; the mobile app is a thin client consuming the REST API.

## Components

### Server (gps-api)

- **Purpose**: GPS data ingestion, user authentication, vehicle tracking
- **Responsibilities**: Parse GPRMC GPS data, manage user accounts, serve vehicle locations
- **Dependencies**: MySQL, Fastify JWT auth

### App (rastroapp)

- **Purpose**: Mobile GPS tracking client
- **Responsibilities**: User authentication, real-time vehicle position display on map
- **Dependencies**: react-native-maps, AsyncStorage for multi-account

## Component Diagram

```
Mobile App (Expo/RN)
    │
    │ HTTPS
    ▼
Fastify API Server
    │
    ▼

```

## Data Flow

GPRS devices send GPS data (GPRMC format) → API parses coordinates (DDMM.MMMM to decimal degrees) → Stored in MySQL → Mobile app queries via REST endpoints → Rendered on Google Maps.

## Technology Stack

| Layer | Technology | Purpose |
|-------|------------|---------|
| Mobile | Expo SDK 54 / React Native 0.81 | Cross-platform mobile app |
| API | Fastify 5.x | REST API server |
| Auth | JWT (fastify/jwt) | Authentication |
| ORM | Drizzle ORM 0.44.x | Database access |
| Database | MySQL | Persistent storage |

## Constraints

- Coordinates use GPRS format (DDMM.MMMM), converted to decimal degrees server-side
- Mobile app requires Google Maps API key for Android
- Legacy MD5 password hashing (migration path needed)
